**There is a bug in solution.py.** `to_base` puts the least significant digit first and never reverses the string, so every result comes out backwards. The docstring example `to_base(31, 16)` should give `'1F'` but returns `'F1'`. Output is only correct when the answer is one digit or reads the same both ways (e.g. `'101'`, `'FF'`). The fix would be `result = alphabet[i] + result` on the last line of the loop.
