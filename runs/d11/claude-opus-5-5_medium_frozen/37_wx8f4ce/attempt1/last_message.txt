**`solution.py` has a bug, and its own docstring example fails.** `add` is supposed to sum the even elements at odd indices, but it loops with `range(1, len(lst), 1)`. That step of 1 makes it check every index from 1 up. So `add([4, 2, 6, 7])` returns 8 (2 + 6) instead of the documented 2. The fix would be to change the step to 2: `range(1, len(lst), 2)`.

The tests fall into three groups:
- **Where the docstring and the code agree:** inputs whose correct answer doesn't depend on the bug, such as one or two elements, no even values, zeros, negative numbers, and lists where the even positions hold only odd numbers. Also checks that index 0 is never counted, the input list isn't changed, and the result is an int.
- **What the code actually does:** for example, `[4, 2, 6, 7]` gives 8 and `[1, 3, 2, 5]` gives 2. These pass now but lock in the buggy behaviour, so they will fail once the bug is fixed.
- **What the docstring promises:** 3 cases, including the docstring example, marked `xfail(strict=True)`. They fail today as expected. If the bug is fixed they will start passing, and strict mode then reports that as a failure, so whoever fixes it knows to remove the marker and delete the second group.
