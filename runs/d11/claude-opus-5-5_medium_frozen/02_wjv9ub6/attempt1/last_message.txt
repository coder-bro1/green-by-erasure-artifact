I wrote the tests, but they can't all pass without changing solution.py, because the bug is in solution.py itself. `sort_numbers` doesn't sort.

**The bug:** solution.py builds the `value_map` dictionary but never uses it. The last line is:
```python
return ' '.join([x for x in numbers.split(' ') if x])
```
All it does is drop extra spaces; the words come back in their original order. Even the docstring's own example fails: `sort_numbers('three one five')` returns `'three one five'` instead of `'one three five'`.

**Tests:** <work>/work/test_solution.py has 19 tests that check what the docstring describes: the docstring example, an empty string, each of the ten words on its own, input that's already sorted, reversed input, mixed order, repeated words, extra spaces, and a case where alphabetical and numerical order differ (`'eight two'` should give `'two eight'`).

**Result of `python -m pytest -q test_solution.py`:** 13 passed, 6 failed. The 6 failures (`test_docstring_example`, `test_reverse_order`, `test_mixed_order`, `test_duplicates_preserved`, `test_extra_spaces_ignored`, `test_alphabetical_order_is_not_used`) are exactly the cases where the words have to be reordered.

I didn't rewrite the tests to expect the current output, because then they would just confirm the bug. The fix is one line in solution.py, which I didn't touch:
```python
return ' '.join(sorted([x for x in numbers.split(' ') if x], key=lambda x: value_map[x]))
```
With that change, all 19 tests should pass.
