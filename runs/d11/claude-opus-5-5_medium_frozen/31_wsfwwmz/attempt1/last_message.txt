**The bugs in `multiply`:**
1. The return line is `return abs(a % 10) * abs(b % 10) * a * b`. The extra `* a * b` at the end multiplies the answer by the full inputs. So `multiply(148, 412)` returns 975616 instead of 16. Three of the four examples in its own docstring fail; only `(2020, 1851) -> 0` passes.
2. Negative inputs: in Python `a % 10` is never negative, so `abs(a % 10)` gives the wrong last digit for most negative numbers. `-13 % 10` is 7, but the last digit of -13 is 3. The docstring's `-15` example only works because 15 happens to end in 5.
