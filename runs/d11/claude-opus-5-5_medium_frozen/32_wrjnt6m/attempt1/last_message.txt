The tests pass, but they show that `circular_shift` in solution.py is broken. For any shift from 1 up to one less than the number of digits, it returns the number unchanged instead of rotating it. The docstring's own example fails: `circular_shift(12, 1)` returns "12" instead of "21". I ran `python -m pytest -q test_solution.py` in <work>\work: 17 passed, 5 marked as expected failures, 0 failed. solution.py was not modified.

**What passes (17 tests):**
- A shift of 0 returns the original number.
- A shift equal to the number of digits returns the original (includes the docstring example `circular_shift(12, 2) == "12"`).
- A shift larger than the number of digits returns the digits reversed.
- The result is always a string.
- Single-digit numbers come back unchanged for any shift.

**The bug (5 tests):** the `else` branch is
```python
return s[:len(s) - shift] + s[len(s) - shift:]
```
which just puts the string back together as it was. It should be `s[len(s) - shift:] + s[:len(s) - shift]`.
