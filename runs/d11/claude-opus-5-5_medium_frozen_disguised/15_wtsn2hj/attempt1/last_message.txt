**The bug:** the loop that checks for divisors starts at 3 instead of 2:
```python
for d in range(3, size):
```
So any text of length 4 is reported as prime: `length_is_prime("abcd")` returns `True`. 4 is the only wrong case, because every larger even length is caught when it divides by its half.

**How the tests handle it:** `test_length_four_is_not_prime` asserts the correct answer (`False`) and is marked as an expected failure with `strict=True`. Until the bug is fixed it shows up as `xfailed`; once someone changes the loop to `range(2, size)`, it will start reporting as a failure, as a reminder to remove the marker.

**What the tests cover:**
- the three docstring examples
- lengths 0, 1 and 2
- lists of prime and non-prime lengths
- a check against a simple prime function for every length from 0 to 199, skipping 4
- spaces and accented characters count as characters
- lists and tuples work too, since the function only uses `len()`
- the return value is always a `bool`
