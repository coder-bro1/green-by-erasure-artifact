**The bug (<work>\work\solution.py):** the docstring says the function returns the longest string, and the first one if several tie. The loop instead does:
```python
maxlen = max(len(x) for x in strings)
for s in strings:
    if len(s) > maxlen:
        return s
```
`maxlen` is already the largest length in the list, so `len(s) > maxlen` can never be true. The loop never returns anything and the function falls through to an implicit `return None`. Even the docstring's own examples fail: `longest(['a','b','c'])` should give `'a'` and `longest(['a','bb','ccc'])` should give `'ccc'`. Changing the condition to `len(s) == maxlen` would fix it and keep the "first one wins" tie rule.
