The tests that pass cover: an empty list, `[0]`, lists of only negative numbers or zeros, docstring examples that contain no positive even numbers (`[-1,-2,0]`, `[9,-2]`), lists of only positive odd numbers, negative odd numbers being ignored, and ordinary floats (1.5, 3.0, 0.1) being ignored.

**Where solution.py doesn't match its docstring (4 strict xfails):**

1. **It never checks that a number is odd.** The code is `sum([i**2 for i in lst if i > 0 and "." not in str(i)])`, so positive even integers are squared and added too.
   - The docstring's own example `double_the_difference([1, 3, 2, 0])` should be 10 but returns 14, because 2² gets added.
   - `[2]` should give 0.
   - `[2, 4, 5, 6, 7]` should give 74 (25 + 49).
   - All three are xfail, and they keep the expected values from the docstring.
2. **The non-integer check is a string hack, `"." not in str(i)`.** `float('inf')` has no "." in its string form, so it isn't ignored, and `double_the_difference([inf, 3])` returns inf instead of 9. This is also xfail. The same hack would let through large floats written in exponent form, like 1e+20.

A fix would be something like `i > 0 and isinstance(i, int) and i % 2 == 1`, but I left solution.py as it is, as instructed.
